AS THE APP · WHEN A TICKET CHANGES
⚡

Trigger

A ticket in a configured project is created or updated. The event only queues a build, so Jira never waits, and one build runs per ticket at a time.

Jira trigger · Forge queue · per-ticket lock · newer change wins
↓
🔍

Retrieve

Related incidents, past resolutions and runbooks are fetched live from the projects and Confluence spaces the admin chose. There is no index to go stale.

JQL · CQL · bounded candidate sets
↓
⇅

Rank

Distinctive keywords pick the candidates; embeddings re-rank them and drop weak matches. One fixed formula, so the same data always gives the same order.

Jina v5 · 60% floor · keyword fallback
↓
✎

Generate

The model writes short claims, each citing one source in that source's own words. They are stored unverified, with links and short excerpts, never full pages.

Qwen3-235B on Amazon Bedrock · DeepSeek v3.2 fallback
CONTEXT BUNDLE IN FORGE KVSstored once per ticket · nothing shown until it passes the next step

Authorize and verify THE SAFETY BOUNDARY

Jira and Confluence are checked as the person reading; anything they can't see is left out without a trace. Each claim must match its source's current text word for word, or it is rejected and counted.
